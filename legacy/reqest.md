sindbadbookmarks 要件定義書 (Version 1.3)最終更新日: 2026-04-04本ドキュメントは、伝説的なLGBTコミュニティポータル「sindbadbookmarks」をモダンな技術スタックを用いて再構築するための要件定義書です。1. プロジェクトビジョンと概要ショップ、団体、メディアに関する情報を、ジャンル、地域、サービスカテゴリー別に登録・閲覧できるポータルサイトを再構築します。LGBTQ+関連の情報を「見つける、登録する、リスト化する」ためのハブを提供し、コミュニティのリソースへのアクセス性と可視性を高めることを目的としています。2. 技術スタックフロントエンド: Next.js複雑なデータ要件や動的なルーティング（App Router）に対応し、フルスタックな機能を提供するNext.jsを採用します。データベース・認証・API: Supabase (PostgreSQL, Auth, Edge Functions)ホスティング・CDN: Cloudflare (Pages / Workers) または Vercel (Next.jsとの親和性を考慮)3. ユーザーロールと認証システムシステムには以下の3つのロールを定義します。Visitor (未ログインユーザー)認証なしで情報の検索、閲覧、絞り込み、ダッシュボードの集計数の確認が可能。通報機能: 掲載されている不適切な情報（リスト）に対して、運営（管理者）へ報告を送信することができる。Contributor (情報登録者)認証方法: Google認証 (OAuth)、もしくはメールアドレスとパスワードによるアカウント作成を可能とする。パスワードリセット機能も必須で実装する。権限: Visitorの権限に加え、新規情報の登録が可能。自分が登録した情報のみ編集・更新ができる。利用停止: アカウントが管理者によって利用停止（Suspended）状態にされた場合、情報の新規登録および編集権限を失う。Admin (管理者)認証方法: 管理者は一般公開用のポータルサイトとは分離された管理者専用サイトからログインを行う。権限: 登録された情報の精査、不適切なコンテンツの削除（非表示化）権限、Visitorからの通報内容の確認、および不適切なContributorのアカウントを利用停止（Suspend）する権限を持つ。4. Supabase RLS（行レベルセキュリティ）設計Supabaseのフロントエンドからの直接アクセスを安全に行うため、PostgreSQLの機能であるRow Level Security (RLS) を厳密に設計します。Contributor（一般登録者）の制御:情報（リスト）が格納されるテーブルにおいて、SELECT は全ユーザー（anon, authenticated）に許可する。INSERT はログイン済みユーザー（authenticated）かつ、profiles テーブルで利用停止状態でない（is_suspended = false）ユーザーのみに許可する。UPDATE および DELETE 操作については、RLSポリシーにて USING (auth.uid() = user_id) を設定し、自分自身のUIDとレコードの作成者IDが一致し、かつ利用停止状態でない場合のみ操作を許可する。Admin（管理者）の制御:管理者は専用の管理サイトを利用してデータベース操作を行う。管理サイトのバックエンド処理においては、RLSをバイパスする権限を持つ Service Role Key を利用するか、Supabase Authのカスタムクレーム（JWT）等で管理者ロールを付与した上で特権操作（情報の精査・削除・アカウント停止）を実行するアーキテクチャとする。通報機能の制御:通報データを保存するテーブルへの INSERT は全ユーザー（未ログインのVisitor含む）に許可し、SELECT は管理者のみに制限する。5. 情報の分類と「Friendliness」の設定情報は以下の軸で整理・分類されます。種別: ショップ（バー、カフェ、サウナなど）、団体/コミュニティ/NPO、メディア/Webサービス/アプリ大・中分類:目的: 交流/出会い、支援/相談、ナイトライフ、文化/アートなど。業種: 飲食、宿泊、美容/ファッション、医療/メンタルヘルスなど。「Friendliness」の属性設定これまでの大まかな「Dedicated / Friendly / Ally」という枠組みを活用しますが、ジャンルの階層構造に組み込むのではなく、「住所」や「連絡先」と同レベルの施設の属性データとして持たせます。任意入力: 情報登録時（Contributorによる入力時）に、この項目の選択は**任意（選択しなくてもよい）**レベルの設定とします。6. データベース設計 (主要テーブル)Supabase (PostgreSQL) 開発ロードマップ (フェーズ分け)Phase 1: 基盤構築と認証Supabaseプロジェクトのセットアップ、Next.jsの初期構築。Google Auth・メールアドレス/パスワード認証、およびパスワードリセット機能の実装。ジャンルや地域ごとの登録数を示すダッシュボード（トップページ）の作成。Phase 2: 情報登録と閲覧 (フロントエンド)Contributorによる登録フォーム（Friendlinessの任意属性などを含む）の実装。RLSポリシーによる自己データの保護および利用停止（Suspend）アカウントの制限実装。Visitor向けの通報フォーム（不適切報告）の実装。キーワード検索、多角的なフィルタリング機能、マップ連携を含む詳細ページの実装。Phase 3: 管理者専用サイトの構築別リポジトリまたは独立した環境として管理パネルを構築。情報の精査機能、削除（非表示化）権限、通報内容の確認機能の実装。Contributorアカウントの利用停止（Suspend）機能の実装。Phase 4: 将来の拡張機能多言語対応（英語）、レビュー機能、イベント情報、お気に入り/ブックマーク機能の実装。8. 非機能要件パフォーマンス: Next.jsによる最適なレンダリング（SSR/SSG）を行い、ダッシュボードの読み込みを2秒以内に抑える。アクセシビリティ・SEO: WCAG 2.1 AA準拠。メタデータおよびOGP設定をNext.jsのビルトイン機能で最適化する。モバイルファースト: レスポンシブデザインの採用。
